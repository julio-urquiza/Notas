En un proyecto de Node.js/Express/React, `dotenv` se instala desde npm y se carga al iniciar la aplicación.

## 1. Instalar dotenv

```bash
npm install dotenv
```

Si usás `yarn`:

```bash
yarn add dotenv
```

---

## 2. Crear el archivo `.env`

En la raíz del proyecto:

```env
PORT=3000
MONGO_URI=mongodb://localhost:27017/miapp
JWT_SECRET=miclave
```

---

## 3. Cargar dotenv

Lo más común es hacerlo al inicio de tu aplicación, por ejemplo en `app.js` o `server.js`:

```js
import dotenv from 'dotenv';

dotenv.config();
```

Con CommonJS:

```js
const dotenv = require('dotenv');

dotenv.config();
```

---

## 4. Usar variables de entorno

Después podés acceder a ellas con `process.env`:

```js
const port = process.env.PORT;

app.listen(port, () => {
  console.log(`Servidor corriendo en puerto ${port}`);
});
```

---

## 5. Estructura típica

```txt
project/
├── src/
│   └── app.js
├── .env          // en la raiz siempre
├── .gitignore
├── package.json
```

---

## 6. Importante: agregar `.env` al `.gitignore`

```gitignore
/node_modules
.env
```

Porque ahí van secretos y configuraciones sensibles.

---

## 7. Forma más profesional

En proyectos más organizados suele abstraerse la configuración:

### `src/config/env.js`

```js
import dotenv from 'dotenv';

dotenv.config();

export const env = {
  port: process.env.PORT,
  mongoUri: process.env.MONGO_URI,
  jwtSecret: process.env.JWT_SECRET,
};
```

Y después:

```js
import { env } from './config/env.js';

console.log(env.port);
```

Esto evita usar `process.env` por toda la aplicación y centraliza la configuración.
