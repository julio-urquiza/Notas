En una aplicación con [Express.js](https://expressjs.com/?utm_source=chatgpt.com), normalmente los tokens se crean para autenticación usando JWT (_JSON Web Token_).  
La librería más usada es [jsonwebtoken](https://www.npmjs.com/package/jsonwebtoken?utm_source=chatgpt.com).

## 1. Instalar dependencias

```bash
npm install jsonwebtoken
```

Y generalmente también:

```bash
npm install dotenv
```

---

## 2. Guardar la clave secreta

`.env`

```env
JWT_SECRET=mi_clave_super_secreta
```

---

## 3. Crear el token

Ejemplo típico en un `authService` o `authController`:

```js
import jwt from 'jsonwebtoken';

export const login = async (req, res) => {
  const user = {
    id: 1,
    email: 'julio@email.com',
    role: 'admin'
  };

  const token = jwt.sign(
    {
      id: user.id,
      email: user.email,
      role: user.role
    },
    process.env.JWT_SECRET,
    {
      expiresIn: '1h'
    }
  );

  res.json({
    token
  });
};
```

---

## ¿Qué hace `jwt.sign()`?

```js
jwt.sign(payload, secret, options)
```

### Payload

Información que querés guardar dentro del token.

```js
{
  id: user.id,
  email: user.email
}
```

### Secret

Clave privada usada para firmar el token.

```js
process.env.JWT_SECRET
```

### Options

Configuraciones adicionales.

```js
{
  expiresIn: '1h'
}
```

## Ejemplo de token generado

Un JWT tiene esta forma:

```txt
xxxxx.yyyyy.zzzzz
```

Son 3 partes:

1. Header
    
2. Payload
    
3. Signature

## Arquitectura profesional

Normalmente no se crea el token directamente en el controller.  
Se abstrae en una utilidad o servicio.

### Ejemplo

#### `utils/jwt.js`

```js
import jwt from 'jsonwebtoken';

export const generateToken = (payload) => {
  return jwt.sign(
    payload,
    process.env.JWT_SECRET,
    {
      expiresIn: '1h'
    }
  );
};
```

---

#### `auth.service.js`

```js
import { generateToken } from '../utils/jwt.js';

export const loginUser = async (email, password) => {
  // validar usuario

  const user = {
    id: 1,
    email
  };

  const token = generateToken({
    id: user.id,
    email: user.email
  });

  return token;
};
```

---

#### `auth.controller.js`

```js
export const login = async (req, res) => {
  const token = await loginUser(
    req.body.email,
    req.body.password
  );

  res.json({ token });
};
```

---

## Luego: verificar token

Después necesitás un middleware para validar el token en rutas protegidas.

```js
jwt.verify(token, process.env.JWT_SECRET)
```

Ejemplo típico:

```js
const decoded = jwt.verify(token, process.env.JWT_SECRET);
```

---

## Flujo completo de autenticación

1. Usuario hace login
    
2. Backend valida credenciales
    
3. Backend genera JWT
    
4. Backend devuelve token
    
5. Front guarda token
    
6. Front envía token en cada request
    

```http
Authorization: Bearer TOKEN
```

7. Middleware verifica token
    
8. Si es válido → acceso permitido
    

---

## Qué suele guardarse dentro del token

Normalmente:

```js
{
  id,
  role,
  email
}
```

No se suele guardar:

- passwords
    
- información sensible
    
- datos enormes
    

Porque el JWT puede decodificarse fácilmente (aunque no modificarse).
