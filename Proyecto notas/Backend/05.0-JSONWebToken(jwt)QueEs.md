JWT significa **JSON Web Token**.

Es un estándar para representar información de forma segura entre dos partes, normalmente:

```txt
cliente ↔ servidor
```

Se usa muchísimo en autenticación y manejo de sesiones en APIs REST.

---

# Idea principal

Cuando un usuario hace login:

1. El servidor valida usuario y contraseña
    
2. El servidor genera un JWT
    
3. El cliente guarda ese token
    
4. El cliente envía el token en cada request
    
5. El servidor verifica el token
    

---

# Ejemplo real

## Login

```http
POST /login
```

Respuesta:

```json
{
  "token": "eyJhbGciOiJIUzI1NiIs..."
}
```

---

# Requests posteriores

```http
GET /profile
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

---

# Qué contiene un JWT

Un JWT tiene 3 partes:

```txt
HEADER.PAYLOAD.SIGNATURE
```

Ejemplo:

```txt
eyJhbGciOiJIUzI1NiIs...
```

---

# 1. Header

Define el tipo de token y algoritmo.

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

---

# 2. Payload

Contiene datos del usuario.

```json
{
  "id": 1,
  "email": "julio@email.com",
  "role": "admin"
}
```

Esto se llama _claims_.

---

# 3. Signature

Firma criptográfica.

Sirve para detectar modificaciones.

Se genera usando:

HMACSHA256(\text{base64UrlEncode(header)} + "." + \text{base64UrlEncode(payload)},\ secret)

Si alguien modifica el payload:

```json
{
  "role": "superadmin"
}
```

la firma deja de coincidir y el token se invalida.

---

# Importante

## JWT NO está encriptado

Está codificado en Base64URL.

Cualquiera puede leer el payload.

Por eso NO se guarda:

- passwords
- tarjetas
- datos sensibles

---
# Qué sí suele guardarse

```json
{
  "id": 1,
  "role": "admin"
}
```

---
# Flujo completo

```txt
Frontend
   ↓ login
Backend
   ↓ valida usuario
Backend
   ↓ genera JWT
Frontend
   ↓ guarda token
Frontend
   ↓ manda token en cada request
Backend
   ↓ verifica token
Backend
   ↓ autoriza acceso
```

---

# Ventaja principal

JWT es **stateless**.

El servidor no necesita guardar sesiones en memoria o base de datos.

El token ya contiene la información necesaria.

---

# Diferencia con sesiones tradicionales

## Session-based auth

Servidor guarda sesión:

```txt
server memory/database
```

El cliente solo tiene un session id.

---

## JWT auth

El cliente guarda todo el token.

El servidor solo lo verifica.

Muy útil para:

- APIs REST
    
- microservicios
    
- frontend separado (React/Vue/etc.)
    
- mobile apps
    

---

# Desventajas

JWT también tiene problemas:

- invalidar tokens no es trivial
    
- logout es más complejo
    
- tokens robados siguen funcionando hasta expirar
    
- payload demasiado grande empeora requests
    

Por eso suelen usarse:

- access token corto
    
- refresh token separado
    

---

# Arquitectura típica moderna

```txt
   ↓

   ↓

```
