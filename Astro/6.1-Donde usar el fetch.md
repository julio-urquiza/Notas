Excelente pregunta 👏 — y es **clave** entender esto bien en Astro,  
porque **dónde ponés el `fetch` cambia totalmente su comportamiento** ⚙️

Vamos a dividirlo en dos casos según **dónde y cómo querés usar los datos**:

---

## 🧠 1️⃣ — Fetch en el **bloque superior** del `.astro`

📍(Server-side: antes de renderizar la página)

Esto se ejecuta **en el servidor** (Node o el adaptador de Astro),  
nunca en el navegador. Es ideal para traer datos **estáticos o semiestáticos**  
(blog, productos, posts, etc.)

```astro
---
const res = await fetch("https://jsonplaceholder.typicode.com/posts/1");
const data = await res.json();
---

<h1>{data.title}</h1>
<p>{data.body}</p>
```

✅ Ventajas:

- Más rápido (Astro renderiza HTML directamente).
- No expone tu API key.
- No carga JS en el cliente.
- Ideal para **SEO** y contenido fijo.

🚫 Desventajas:

- El usuario **no puede interactuar** con los datos.
- Si querés actualizarlos sin recargar, no podés (no hay JS activo).

---

## ⚙️ 2️⃣ — Fetch dentro de un **componente React/Vue/Svelte**

📍(Client-side: en el navegador)

Esto se ejecuta **en el navegador** cuando el componente se carga.  
Es útil cuando necesitás **interacción o datos que cambian constantemente.**

```astro
---
import UserCard from "../components/UserCard.jsx";
---

<UserCard client:load />
```

📁 `UserCard.jsx`:

```jsx
import { useEffect, useState } from "react";

export default function UserCard() {
  const [user, setUser] = useState(null);

  useEffect(() => {
    fetch("https://jsonplaceholder.typicode.com/users/1")
      .then((res) => res.json())
      .then(setUser);
  }, []);

  if (!user) return <p>Cargando...</p>;

  return (
    <div className="p-4 border rounded-lg">
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  );
}
```

✅ Ventajas:

- Podés actualizar los datos en tiempo real.
- Permite interacción y reactividad.
- Ideal para dashboards, formularios, chats, etc.

🚫 Desventajas:

- Carga un poco de JS en el navegador.
- No se renderiza en el servidor (menos SEO).

---

## 🧩 En resumen:

|Dónde ponés el `fetch`|Cuándo se ejecuta|Cuándo usarlo|
|---|---|---|
|En la parte superior del `.astro`|En el servidor, al generar HTML|Cuando los datos son públicos, estáticos o no cambian mucho|
|Dentro de un `.jsx` o `.vue` con `client:...`|En el navegador|Cuando querés interacción o datos dinámicos|

---

💡 **Regla práctica:**

- Si el usuario **no necesita refrescar los datos** → `fetch` en el `.astro`
- Si los datos **tienen que actualizarse sin recargar** → `fetch` dentro del componente (React/Vue/Svelte)

---
## 🌍 Ejemplo completo: página de usuarios

Imaginemos que queremos una página `/usuarios` que:

1. Muestre una **lista de usuarios** traída desde la API (server-side).
2. Tenga un **componente interactivo** que busque un usuario (client-side).

---

## 🧱 Paso 1: crear la página `/src/pages/usuarios.astro`

```astro
---
import BuscadorUsuario from "../components/BuscadorUsuario.jsx";

// ✅ SERVER-SIDE FETCH
// Se ejecuta solo en el servidor, antes del render.
const res = await fetch("https://jsonplaceholder.typicode.com/users");
const users = await res.json();
---

<h1 class="text-2xl font-bold mb-4">Lista de usuarios (Server-side)</h1>

<ul class="space-y-2">
  {users.map((u) => (
    <li class="border-b pb-2">{u.name} — {u.email}</li>
  ))}
</ul>

<hr class="my-6" />

<h2 class="text-xl font-semibold mb-2">Buscar usuario (Client-side)</h2>

<!-- ✅ CLIENT-SIDE FETCH -->
<BuscadorUsuario client:load />
```

---

## ⚙️ Paso 2: crear el componente `/src/components/BuscadorUsuario.jsx`

```jsx
import { useState } from "react";

export default function BuscadorUsuario() {
  const [query, setQuery] = useState("");
  const [user, setUser] = useState(null);

  async function buscar() {
    const res = await fetch(`https://jsonplaceholder.typicode.com/users?username=${query}`);
    const data = await res.json();
    setUser(data[0] || null);
  }

  return (
    <div className="p-4 border rounded-lg shadow w-full max-w-md">
      <input
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="Buscar por username (Ej: Bret)"
        className="border p-2 rounded w-full"
      />

      <button
        onClick={buscar}
        className="mt-2 px-4 py-2 bg-blue-600 text-white rounded hover:bg-blue-700 transition"
      >
        Buscar
      </button>

      {user && (
        <div className="mt-4 p-3 border-t">
          <h3 className="font-bold text-lg">{user.name}</h3>
          <p>{user.email}</p>
          <p className="text-sm text-gray-500">{user.company.name}</p>
        </div>
      )}
    </div>
  );
}
```

---

## 🧩 Qué está pasando

|Parte|Tipo de Fetch|Cuándo ocurre|Resultado|
|---|---|---|---|
|`fetch()` arriba del `.astro`|Server-side|Antes de generar el HTML|Muestra la lista inicial de usuarios (HTML estático)|
|`fetch()` dentro de `BuscadorUsuario.jsx`|Client-side|En el navegador, cuando hacés clic en el botón|Busca y muestra un usuario dinámicamente|

---

## ✅ Ventajas de esta combinación

- La página carga rápido y con buen SEO (gracias al fetch del `.astro`).
    
- Luego, el componente React se **monta encima** y permite interacción sin recargar.
    
- Astro optimiza ambos mundos automáticamente:  
    el HTML se sirve estático, pero tu parte interactiva se hidrata en el cliente.
