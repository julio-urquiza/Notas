## Resumen rápido (idea central)

> **`extends` = herencia (qué SOS)**  
> **`implements` = contrato (qué PROMETÉS hacer)**

---

## 1. `extends` – Herencia

Se usa cuando una clase **hereda comportamiento y estructura** de otra clase.

```ts
class Animal {
  eat() {
    console.log("Eating");
  }
}

class Dog extends Animal {
  bark() {
    console.log("Woof");
  }
}
```

Qué implica `extends`:

- Heredás **métodos**
    
- Heredás **propiedades**
    
- Podés **sobrescribir** comportamiento
    
- Existe en runtime (JS)
    

```ts
const dog = new Dog();
dog.eat();  // heredado
dog.bark(); // propio
```

---

### `extends` con clases abstractas

```ts
abstract class Repository<T> {
  abstract findById(id: string): Promise<T | null>;

  protected log(msg: string) {
    console.log(msg);
  }
}

class UserRepository extends Repository<User> {
  async findById(id: string) {
    this.log("Buscando user");
    return null;
  }
}
```

✔️ Reutilización de lógica  
✔️ Jerarquía clara  
✔️ Una sola clase base

---

## 2. `implements` – Contrato

Se usa cuando una clase **se compromete a cumplir una interface**.

```ts
interface Flyable {
  fly(): void;
}

class Bird implements Flyable {
  fly() {
    console.log("Flying");
  }
}
```

Qué implica `implements`:

- **No hereda código**
    
- Solo obliga a implementar métodos
    
- Desaparece en runtime
    
- Es 100% TypeScript
    

---

### Error típico que evita `implements`

```ts
class Bird implements Flyable {
  // ❌ Error: falta fly()
}
```

TypeScript te obliga a cumplir el contrato.

---

## 3. Diferencia CLAVE (en una frase)

> `extends` **reutiliza implementación**  
> `implements` **solo valida forma**

---

## 4. Pueden usarse juntos (muy común)

```ts
interface Repository<T> {
  findById(id: string): Promise<T | null>;
}

abstract class BaseRepository<T> implements Repository<T> {
  abstract findById(id: string): Promise<T | null>;
}
```

Y luego:

```ts
class ProductRepository
  extends BaseRepository<Product>
  implements Repository<Product> {
    
  async findById(id: string) {
    return null;
  }
}
```

Esto:

- Hereda lógica (`extends`)
    
- Cumple contrato (`implements`)
    

---

## 5. `extends` con interfaces (detalle importante)

En TypeScript, una **interface puede extender otra interface**:

```ts
interface A {
  a: string;
}

interface B extends A {
  b: number;
}
```

Pero:

- Una clase **NO puede extender una interface**
    
- Una clase **SÍ puede implementar varias interfaces**
    

---

## 6. Comparación directa

|Aspecto|extends|implements|
|---|---|---|
|Tipo|Herencia|Contrato|
|Reutiliza código|Sí|No|
|Runtime|Sí|No|
|Cantidad|1 clase|Múltiples interfaces|
|Obliga métodos|No (ya existen)|Sí|

---

## 7. Regla profesional para no equivocarte

Memorizá esto:

> **Usá `extends` cuando necesitás comportamiento compartido**  
> **Usá `implements` cuando necesitás reglas que se cumplan**

---

## 8. Errores comunes (muy vistos)

❌ Usar `extends` solo para tipar  
❌ Usar clases en vez de interfaces como contratos  
❌ Herencias profundas innecesarias

---

## 9. Diseño recomendado (industria)

- Interfaces → contratos públicos
    
- Clases abstractas → base reutilizable
    
- Clases concretas → implementación real
    

---

## Frase final para fijarlo

> **Herencia es “soy un” (`extends`)**  
> **Contrato es “me comprometo a” (`implements`)**
