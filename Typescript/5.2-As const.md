## Qué hace `as const` (idea central)

> **`as const` le dice a TypeScript:  
> “Esto es un valor literal e inmutable. No lo generalices.”**

Dos efectos **simultáneos**:

1. 🔒 **Hace el valor readonly**
    
2. 🎯 **Evita que los tipos se amplíen (`widening`)**
    

---

## El problema SIN `as const`

```ts
const statuses = ["PENDING", "APPROVED", "REJECTED"];
```

TypeScript infiere:

```ts
string[]
```

¿Por qué?  
Porque asume:

> “Es un array de strings que puede cambiar”

Entonces:

```ts
statuses[0] // string
```

❌ Perdimos la información de los valores reales.

---

## Qué pasa CON `as const`

```ts
const statuses = ["PENDING", "APPROVED", "REJECTED"] as const;
```

TypeScript ahora infiere:

```ts
readonly ["PENDING", "APPROVED", "REJECTED"]
```

Esto significa:

- Array **inmutable**
    
- Cada elemento es un **literal**, no `string`
    

---

## Comparación clara

|Sin `as const`|Con `as const`|
|---|---|
|`string[]`|`readonly ["PENDING", "APPROVED", "REJECTED"]`|
|mutable|inmutable|
|pierde valores|conserva valores|
|menos seguro|muy seguro|

---

## Para qué sirve realmente

Ahora esta línea **cobra sentido**:

```ts
type Status = typeof statuses[number];
```

Desglosemos eso.

---

## `typeof statuses`

```ts
typeof statuses
```

Produce:

```ts
readonly ["PENDING", "APPROVED", "REJECTED"]
```

---

## `[number]` (indexed access type)

```ts
typeof statuses[number]
```

Se lee como:

> “Dame el tipo de cualquier elemento del array”

Resultado:

```ts
"PENDING" | "APPROVED" | "REJECTED"
```

🎯 **Unión literal exacta**.

---

## Resultado final

```ts
type Status = "PENDING" | "APPROVED" | "REJECTED";
```

Sin escribirlo a mano.  
Sin enums.  
Sin duplicar valores.

---

## Analogía mental (muy útil)

Pensalo así:

```ts
const x = "hola";        // tipo: string
const y = "hola" as const; // tipo: "hola"
```

`as const` le dice a TS:

> “No es _cualquier_ string, es _este_ string”.

---

## Dónde se usa en la práctica

### 1. Estados

```ts
const STATUSES = ["IDLE", "LOADING", "SUCCESS", "ERROR"] as const;
type Status = typeof STATUSES[number];
```

---

### 2. Roles / permisos

```ts
const ROLES = ["ADMIN", "USER"] as const;
type Role = typeof ROLES[number];
```

---

### 3. Configuraciones

```ts
const CONFIG = {
  mode: "dark",
  version: 1
} as const;
```

Todo queda:

- Literal
    
- Readonly
    
- Seguro
    

---

## Qué NO hace `as const`

❌ No convierte valores en runtime  
❌ No valida datos externos  
❌ No reemplaza type guards

Es **100% TypeScript**, solo en compilación.

---

## Regla de oro para usarlo

Usá `as const` cuando:

- Definís constantes
    
- Querés unions automáticas
    
- No querés enums
    
- Querés máxima seguridad
    

---

## Frase para recordar

> **`as const` congela el valor y preserva su tipo literal.**
