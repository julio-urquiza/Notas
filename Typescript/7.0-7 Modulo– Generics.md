## Objetivo real

👉 Escribir **código reutilizable**  
👉 Sin perder **seguridad de tipos**  
👉 Evitando `any` y casteos (`as`)

---

## 1. Generics en funciones

### El problema sin generics

```ts
function wrap(value: any): any[] {
  return [value];
}
```

❌ Perdés tipo  
❌ Autocompletado roto  
❌ Errores en runtime

---

### Solución con generics

```ts
function wrap<T>(value: T): T[] {
  return [value];
}
```

Qué significa `<T>`:

- `T` es un **placeholder de tipo**
    
- Se define en tiempo de compilación
    
- Se infiere automáticamente
    

---

### Uso real

```ts
wrap(10);        // number[]
wrap("hola");    // string[]
wrap({ id: 1 }); // { id: number }[]
```

TypeScript **recuerda el tipo exacto**.

---

## 2. Inferencia (no hay que pasar `<T>`)

```ts
wrap<number>(10); // válido, pero innecesario
wrap(10);         // TS infiere T = number
```

Regla:

> **Si TS puede inferir, dejalo inferir.**

## 3. Generics en interfaces

```ts
interface ApiResponse<T> {
  data: T;
  error: string | null;
}
```

Uso:

```ts
const response: ApiResponse<User> = {
  data: { id: 1, name: "Juan" },
  error: null
};
```

Esto es **arquitectura real de APIs**.

---

## 4. Generics en clases

```ts
class Box<T> {
  constructor(private value: T) {}

  getValue(): T {
    return this.value;
  }
}
```

Uso:

```ts
const box = new Box<string>("hola");
box.getValue(); // string
```

## 5. Constraints (`extends`) – MUY IMPORTANTE

Ahora entramos en lo potente.

---

### El problema

```ts
function getId<T>(obj: T): string {
  return obj.id; // ❌ Error
}
```

TypeScript no sabe que `T` tiene `id`.

---

### Solución con constraint

```ts
function getId<T extends { id: string }>(obj: T): string {
  return obj.id;
}
```

Se lee así:

> “T puede ser cualquier cosa,  
> **pero tiene que tener `id: string`**”

---

### Uso

```ts
getId({ id: "1", name: "Test" }); // OK
getId({ name: "Test" });          // Error
```

---

## 6. Constraints con interfaces

```ts
interface Identifiable {
  id: string;
}

function getId<T extends Identifiable>(obj: T): string {
  return obj.id;
}
```

Más limpio y reutilizable.

---

## 7. Generics + keyof (nivel avanzado)

```ts
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
```

Uso:

```ts
const user = { id: 1, name: "Ana" };

getProperty(user, "id");   // number
getProperty(user, "name"); // string
getProperty(user, "age");  // ❌ Error
```

Esto es **TypeScript en su máxima expresión**.

---

## 8. Error común (muy visto)

❌ Esto:

```ts
function identity<T extends any>(value: T): T {
  return value;
}
```

No aporta nada. `extends any` es inútil.

---

## 9. Cuándo usar generics (regla real)

Usalos cuando:

- El tipo **depende del uso**
    
- El comportamiento es el mismo
    
- Querés reutilización real
    

NO los uses:

- Para “todo”
    
- Para funciones específicas
    
- Cuando un tipo concreto es más claro
