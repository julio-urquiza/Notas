## 1. `coordinates` ✅ **Correcto**

```ts
const coordinates: [number, number] = [40.7128, -74.0060];
```

✔️ Orden fijo  
✔️ Tipos correctos  
✔️ Uso apropiado de tuple

**Aprobado sin cambios.**

---

## 2. `statuses` ⚠️ **Funciona, pero no es lo ideal**

```ts
const statuses: [string, string, string] = ["PENDING", "APPROVED", "REJECTED"];
```

Esto **compila**, pero semánticamente **no es una buena tuple**.

### Por qué

- No importa el orden
    
- No hay significado posicional
    
- Es una lista de valores homogéneos
    

👉 Esto **NO es un buen caso de tuple**.

---

### Forma profesional recomendada

#### Opción A: Array + union

```ts
const statuses = ["PENDING", "APPROVED", "REJECTED"] as const;

type Status = typeof statuses[number];
```

Ahora:

```ts
let s: Status;
s = "PENDING";  // OK
s = "INVALID";  // Error
```

---

#### Opción B: Array tipado

```ts
const statuses: string[] = ["PENDING", "APPROVED", "REJECTED"];
```

Si solo necesitás recorrerlos.

---

### Regla clara

> **Tuple solo cuando el orden importa.**  
> Si no, usá array.

---

## 3. `result` ⚠️ **Correcto pero incompleto como patrón real**

```ts
const result: [null, User] = [null, { id: "1", name: "Test" }];
```

Esto es válido, pero en la práctica suele modelarse así:

---

### Patrón industrial `[error, data]`

```ts
type Result<T> = [Error | null, T | null];

const result: Result<User> = [null, { id: "1", name: "Test" }];
```

Ahora podés tener:

```ts
[error, user]
```

con combinaciones válidas y tipadas.

---

## Versión aún mejor (readonly)

```ts
type Result<T> = readonly [Error | null, T | null];
```

Evita mutaciones accidentales.
