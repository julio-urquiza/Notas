
_(parámetros, retornos, async y contratos)_

## Objetivo del módulo

Que tus funciones:

- Expresen **contratos claros**
    
- Sean **predecibles**
    
- Eviten errores de runtime
    
- Sean fáciles de refactorizar
    

En TypeScript:

> **Una función mal tipada es una API rota.**

---

## 1. Tipos en parámetros (lo mínimo indispensable)

En JS:

```js
function calculateTotal(price, tax) {
  return price + price * tax;
}
```

Problemas:

- No sabés qué recibe
    
- No sabés qué devuelve
    
- No hay validación previa
    

En TypeScript:

```ts
function calculateTotal(price: number, tax: number): number {
  return price + price * tax;
}
```

Ahora:

- El contrato es explícito
    
- El compilador protege el uso
    
- El IDE autocompleta correctamente
    

---

## 2. Tipos de retorno (no siempre obligatorios)

TypeScript **puede inferir el retorno**, pero **no siempre conviene**.

Ejemplo con inferencia:

```ts
function sum(a: number, b: number) {
  return a + b;
}
```

TS infiere:

```ts
(a: number, b: number) => number
```

### ¿Cuándo tipar explícitamente el retorno?

✔️ Funciones públicas  
✔️ Servicios  
✔️ APIs  
✔️ Funciones complejas  
✔️ Cuando querés evitar cambios accidentales

Ejemplo:

```ts
function getStatus(): "OK" | "ERROR" {
  return "OK";
}
```

Si mañana alguien retorna `"SUCCESS"`, TS falla.  
Eso es **protección de contrato**.

---

## 3. `void` en funciones con side effects

Ya lo usaste correctamente:

```ts
function logMessage(message: string): void {
  console.log(message);
}
```

Puntos clave:

- `void` no significa “no hay return”
    
- Significa “el valor retornado no importa”
    

Esto es importante en:

- Callbacks
    
- Event handlers
    
- Servicios de escritura
    

---

## 4. Funciones `async` y `Promise<T>`

Regla absoluta:

> **Toda función `async` retorna una `Promise`**

Ejemplo correcto:

```ts
async function getUser(id: string): Promise<User> {
  return {
    id,
    email: "test@mail.com",
    status: "ACTIVE"
  };
}
```

Ejemplo incorrecto (conceptualmente):

```ts
async function getUser(id: string): User { // ❌
  ...
}
```

TypeScript lo marca como error.

---

## 5. `Promise<void>` (muy común)

```ts
async function saveUser(user: User): Promise<void> {
  // guarda en DB
}
```

Uso típico:

- Writes
    
- Logs
    
- Side effects
    
- Comandos (CQRS)
    

---

## 6. Funciones que retornan `null` o `undefined`

Con `strict: true`, esto es importante.

Ejemplo:

```ts
function findUser(id: string): User | null {
  return null;
}
```

El consumidor está obligado a validar:

```ts
const user = findUser("1");

if (!user) {
  // manejar error
}
```

Esto evita:

- `Cannot read property 'x' of null`
    
- Bugs clásicos de JS
    

---

## 7. Function overloads (nivel intermedio–alto)

Los **overloads** permiten **múltiples contratos** para una misma función.

Ejemplo clásico:

```ts
function format(value: string): string;
function format(value: number): string;
function format(value: string | number): string {
  if (typeof value === "number") {
    return value.toFixed(2);
  }
  return value.toUpperCase();
}
```

Claves:

- Las firmas son el contrato público
    
- La implementación es única
    
- El consumidor solo ve las firmas
    

---

## 8. Por qué NO usar unions en lugar de overloads

Esto:

```ts
function format(value: string | number): string {
  ...
}
```

Funciona, pero:

- El consumidor no ve variantes claras
    
- Se pierde expresividad
    

Overloads:

- Documentan la API
    
- Mejoran DX
    
- Evitan mal uso
    

---

## 9. Callbacks tipados

Muy común en:

- Eventos
    
- Array methods
    
- APIs
    

Ejemplo:

```ts
function processItems(
  items: number[],
  callback: (item: number) => void
): void {
  items.forEach(callback);
}
```

Uso:

```ts
processItems([1, 2, 3], (item) => {
  console.log(item.toFixed(2));
});
```

TypeScript infiere el tipo del callback automáticamente.

---

## 10. Funciones como tipos

Esto es **muy usado** en arquitectura limpia.

```ts
type Logger = (message: string) => void;
```

Uso:

```ts
const logger: Logger = (msg) => {
  console.log(msg);
};
```

Esto permite:

- Inyección de dependencias
    
- Tests fáciles
    
- Contratos claros
    

---

## 11. Errores comunes (importante)

❌ No tipar funciones públicas  
❌ Retornos implícitos peligrosos  
❌ `any` en callbacks  
❌ Promises sin tipo  
❌ `async` sin entender `Promise<T>`
