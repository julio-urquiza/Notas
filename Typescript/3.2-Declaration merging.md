# ¿Qué es _declaration merging_ en TypeScript?

**Declaration merging** significa que **TypeScript permite declarar varias veces una misma `interface` y las “fusiona” automáticamente en una sola**.

Esto **NO existe en JavaScript** y **NO es comportamiento estándar en la mayoría de los lenguajes tipados**.

---

## Ejemplo mínimo

```ts
interface User {
  id: string;
}

interface User {
  email: string;
}
```

TypeScript interpreta esto como:

```ts
interface User {
  id: string;
  email: string;
}
```

👉 **No hay error.**  
👉 Las interfaces se **combinan**.

Eso es _declaration merging_.

---

## Por qué TypeScript permite esto

El motivo histórico y técnico es **extender tipos de librerías externas** sin modificar su código.

Ejemplo real:

```ts
// librería externa
interface Window {
  title: string;
}
```

Tu proyecto:

```ts
interface Window {
  myCustomProperty: string;
}
```

Resultado:

```ts
interface Window {
  title: string;
  myCustomProperty: string;
}
```

Esto permite:

- Extender objetos globales
    
- Agregar tipos a librerías JS sin tipado completo
    
- Hacer _module augmentation_
    

📌 **Este es el uso legítimo y correcto**.

---

## Qué se puede “mergear” y qué no

### Se puede

- `interface`
    
- `namespace`
    

### NO se puede

- `type`
    
- `class`
    
- `enum`
    

Ejemplo inválido:

```ts
type User = { id: string };
type User = { email: string }; // ❌ Error
```

Esto **no compila**, a diferencia de `interface`.

---

## Por qué es peligroso en código de dominio

Tu ejemplo anterior:

```ts
interface Product {
  id: string;
}

interface Product {
  status: ProductStatus;
}
```

TypeScript lo acepta, pero:

- El contrato queda **disperso**
    
- No se ve la estructura completa en un solo lugar
    
- Es fácil romper invariantes
    
- En equipos grandes, genera bugs difíciles de rastrear
    

📌 En dominio propio:

> **Declaration merging = mala práctica**

---

## Regla clara de industria

✔️ Usar _declaration merging_ **solo** para:

- Extender librerías
    
- Module augmentation
    
- Tipos globales
    

❌ NO usarlo para:

- Modelar entidades de negocio
    
- Reemplazar herencia
    
- Reemplazar composición
    

---

## Diferencia con herencia y composición

### Declaration merging

```ts
interface User { id: string }
interface User { email: string }
```

Automático, implícito, peligroso.

### Herencia

```ts
interface Admin extends User {
  permissions: string[];
}
```

Explícito, claro, seguro.

### Composición

```ts
type AuditedUser = User & Audit;
```

Explícito, controlado, reutilizable.

---

## Regla mental que te tenés que llevar

> Si ves **dos interfaces con el mismo nombre**, preguntate:
> 
> “¿Estoy extendiendo una librería o estoy creando un bug?”

Si es dominio propio → **está mal**.

---

## Resumen corto

- `declaration merging` = TypeScript fusiona interfaces con el mismo nombre
    
- Es una **feature**, no un bug
    
- Es **útil** para librerías
    
- Es **peligrosa** para dominio
    
- `type` **no** permite merging (por eso a veces se prefiere)
