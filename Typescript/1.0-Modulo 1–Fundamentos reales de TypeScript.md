_(lo que JavaScript NO te da)_
## 1. Qué es TypeScript realmente (sin marketing)

**TypeScript es:**

- Un **superset de JavaScript**
    
- Un **analizador estático de tipos**
    
- Un **compilador** que genera JavaScript
    

**TypeScript NO es:**

- Un runtime
    
- Un reemplazo de JavaScript
    
- Algo que corre en el navegador o en Node
    

👉 **El código TypeScript nunca se ejecuta.**  
Se **compila** a JavaScript y **ese JS es el que corre**.

---

## 2. Qué problema real viene a resolver

JavaScript:

- Es **dinámico**
    
- Permite errores que solo aparecen en runtime
    
- No protege contratos entre funciones, módulos o capas
    

Ejemplo clásico en JS:

```js
function calculateTotal(price, tax) {
  return price + price * tax;
}

calculateTotal("100", 0.21); // runtime bug
```

Esto **no falla al escribirlo**, falla en producción.

TypeScript mueve esos errores a:

- **tiempo de desarrollo**
    
- **antes de ejecutar el código**
    

---

## 3. TypeScript ≠ “JavaScript con tipos”

Este es un error conceptual común.

TypeScript:

- Analiza **flujo**
    
- Analiza **contexto**
    
- Analiza **estructuras**
    
- Hace **narrowing**
    
- Hace **verificación estructural**
    

Ejemplo:

```ts
let x = 10;
x = "hola"; // error
```

Pero también:

```ts
function print(value: string | number) {
  if (typeof value === "string") {
    value.toUpperCase(); // TS entiende el flujo
  }
}
```

👉 TS **razona sobre tu código**, no solo “pone tipos”.

## 4. Primer contacto práctico: instalar y compilar

### Paso 1 – Instalar TypeScript

```bash
npm install -g typescript
```

Verificar:

```bash
tsc --version
```

---

### Paso 2 – Crear archivo TypeScript

```ts
// index.ts
let age: number = 30;
let name: string = "Julio";
let isActive: boolean = true;
```

Compilar:

```bash
tsc index.ts
```

Resultado:

- Se genera `index.js`
    
- El JS **no tiene tipos**
    

```js
let age = 30;
let name = "Julio";
let isActive = true;
```

👉 Los tipos **no existen en el output**.

## 5. Errores en tiempo de compilación (el valor real)

```ts
let total: number = "100";
```

TypeScript:

```
Type 'string' is not assignable to type 'number'
```

Esto **en JavaScript se ejecutaría sin problemas**.  
En TypeScript **ni siquiera compila**.

Esto es lo que pagan las empresas cuando usan TS.

---

## 6. Inferencia de tipos (no sobre-tipar)

Esto está pensado para gente que **ya sabe programar**, como vos.

```ts
let count = 10;
```

TypeScript infiere:

```ts
let count: number
```

Si hacés:

```ts
count = "hola";
```

Error.

👉 **No escribas tipos cuando TS ya los infiere bien.**

Regla profesional:

> Tipá **interfaces, funciones y límites del sistema**, no cada variable local.

---

## 7. any: el anti-TypeScript

```ts
let data: any;
data = 10;
data = "hola";
data = {};
```

Esto:

- Desactiva TypeScript
    
- Elimina seguridad
    
- Es deuda técnica
    

Si no sabés qué tipo es:

```ts
let data: unknown;
```

Diferencia clave:

```ts
let data: unknown;
data.toUpperCase(); // error
```

Con `any` eso pasaría sin avisar.

## 8. tsconfig.json (CLAVE absoluta)

En proyectos reales **nunca se compila un archivo suelto**.  
Se usa un `tsconfig.json`.

Crear:

```bash
tsc --init
```

Archivo importante:

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "commonjs",
    "strict": true,
    "outDir": "./dist",
    "rootDir": "./src"
  }
}
```

### ¿Qué hace `strict: true`?

Activa:

- `noImplicitAny`
    
- `strictNullChecks`
    
- `strictFunctionTypes`
    
- `strictPropertyInitialization`
    

👉 **Sin strict, TypeScript pierde gran parte de su valor.**

En industria:

> TypeScript sin strict = JavaScript caro

---

## 9. Flujo de trabajo real

En la práctica:

1. Escribís `.ts`
    
2. TypeScript valida
    
3. Compila a `.js`
    
4. Node / navegador ejecuta JS
    

Nunca:

- Subís `.ts` a producción
    
- Ejecutás TS directamente (salvo herramientas como ts-node)
    

---

## 10. Resumen mental del módulo 1

Tenés que quedarte con esto:

- TypeScript **no corre**
    
- TypeScript **analiza**
    
- Los errores pasan de runtime → compile time
    
- `strict: true` no es opcional
    
- `any` es el enemigo
    
- Inferencia > tipado manual excesivo
