## Objetivo del módulo

Que entiendas **cómo TypeScript se usa realmente en un backend**, no teoría suelta.

Al terminar este módulo deberías poder:

- Configurar un proyecto Node + TS
    
- Tipar controladores (`req`, `res`)
    
- Usar DTOs
    
- Separar controller / service / repository **con tipos**
    

---

## 1. Qué cambia respecto a JavaScript

### JavaScript puro (Express)

```js
app.get("/users", (req, res) => {
  res.json([]);
});
```

- `req`: cualquier cosa
    
- `res`: cualquier cosa
    
- Sin validación
    
- Errores en runtime
    

---

### TypeScript + Express

```ts
import { Request, Response } from "express";

export const getUsers = (req: Request, res: Response) => {
  res.json([]);
};
```

Vamos por partes.

---

## 2. `Request` y `Response`

```ts
import { Request, Response } from "express";
```

- **TIPO (TypeScript)**: definiciones de Express
    
- **RESULTADO (runtime)**: no cambia nada, sigue siendo Express
    

---

```ts
(req: Request, res: Response)
```

### Qué significa

- **TIPO (TypeScript)**:
    
    - `req` tiene `params`, `query`, `body`, etc.
        
    - `res` tiene `json`, `status`, `send`, etc.
        
- **RESULTADO (runtime)**:
    
    - `req` y `res` son los objetos reales de Express
        

---

## 3. Tipar `req.params`, `req.body`, `req.query`

Este punto es **clave**.

---

### Ejemplo sin tipar

```ts
req.params.id;
```

- **TIPO (TypeScript)**: `any`
    
- ❌ Sin seguridad
    

---

### Ejemplo tipado correctamente

```ts
interface GetUserParams {
  id: string;
}

export const getUser = (
  req: Request<GetUserParams>,
  res: Response
) => {
  const id = req.params.id;
};
```

#### Qué pasa acá

- `Request<GetUserParams>`
    
    - **TIPO (TypeScript)**: `req.params` tiene `{ id: string }`
        
- `req.params.id`
    
    - **RESULTADO (runtime)**: valor real del param
        
    - **TIPO (TypeScript)**: `string`
        

---

## 4. Tipar `req.body` (DTOs)

### DTO = Data Transfer Object

Un objeto que representa **qué datos entran o salen**.

---

### Ejemplo

```ts
interface CreateUserDTO {
  name: string;
  email: string;
  age: number;
}
```

Uso en controller:

```ts
export const createUser = (
  req: Request<{}, {}, CreateUserDTO>,
  res: Response
) => {
  const data = req.body;
};
```

#### Análisis

- `Request<Params, ResBody, ReqBody>`
    
- Acá:
    
    - **TIPO (TypeScript)**: `req.body` es `CreateUserDTO`
        
    - **RESULTADO (runtime)**: JSON enviado por el cliente
        

```ts
data.email;
// RESULTADO (runtime): string real
// TIPO (TypeScript): string
```

## 5. Separación correcta de capas (esto es industria)

### Controller (HTTP)

```ts
export const getUserController = async (
  req: Request<GetUserParams>,
  res: Response
) => {
  const user = await userService.getById(req.params.id);
  res.json(user);
};
```

- Maneja HTTP
    
- No lógica de negocio
    

---

### Service (negocio)

```ts
interface User {
  id: string;
  name: string;
  email: string;
}

class UserService {
  async getById(id: string): Promise<User | null> {
    return null;
  }
}
```

- **TIPO (TypeScript)**: contrato claro
    
- **RESULTADO (runtime)**: lógica real
    

---

### Repository (datos)

```ts
class UserRepository {
  async findById(id: string): Promise<User | null> {
    return null;
  }
}
```

---

## 6. Flujo completo tipado

```ts
HTTP → Controller → Service → Repository
```

Cada capa:

- recibe tipos claros
    
- devuelve tipos claros
    
- no usa `any`
    

---

## 7. Error común (muy importante)

❌ Tipar todo como `any`

```ts
(req: any, res: any)
```

Eso **anula TypeScript**.

---

## 8. Regla mental del módulo

> TypeScript en backend **no es para Express**,  
> es para **modelar datos y contratos entre capas**

## 9. Mini ejemplo completo (resumen)

```ts
interface User {
  id: string;
  name: string;
}

export const getUsers = (
  req: Request,
  res: Response<User[]>
) => {
  res.json([{ id: "1", name: "Ana" }]);
};
```

- **RESULTADO (runtime)**: JSON real
    
- **TIPO (TypeScript)**: `res.json` solo acepta `User[]`
