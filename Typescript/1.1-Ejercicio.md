---

## Error 1 – Reasignación incompatible de tipo

```ts
palabra = 2
```

### Qué dice TypeScript

> Type 'number' is not assignable to type 'string'

### Por qué ocurre

- `palabra` fue declarada como `string`
    
- TypeScript **congela el contrato del tipo**
    
- Intentás asignarle un `number`
    

En JavaScript:

- Esto sería válido
    
- El error aparecería (o no) mucho más tarde
    

En TypeScript:

- **Error en tiempo de compilación**
    
- El código no pasa el chequeo
    

👉 Este error demuestra el **principio básico de TypeScript**:  
**una variable no puede violar su contrato de tipo**.

---

## Error 2 – Método inexistente para el tipo

```ts
numero.split(' ')
```

### Qué dice TypeScript

> Property 'split' does not exist on type 'number'

### Por qué ocurre

- `split()` es un método de `string`
    
- `numero` es de tipo `number`
    
- TypeScript conoce **la API exacta** de cada tipo primitivo
    

Esto es clave:

- TS no solo valida “string vs number”
    
- También valida **qué métodos existen para cada tipo**
    

En JavaScript:

```js
42.split(' ') // error en runtime
```

En TypeScript:

- El error aparece **antes de ejecutar**
    
- Ni siquiera compila
    

---

## Punto MUY importante (detalle de seniority)

Notá que:

```ts
const palabra: string = 'hola'
```

Acá el tipo es **redundante**.

TypeScript ya infiere correctamente:

```ts
const palabra = 'hola' // inferred: string
```

En código profesional, se prefiere:

- Tipar **interfaces**
    
- Tipar **funciones**
    
- Dejar que TS infiera variables simples
    

Esto no es obligatorio, pero es **buena práctica real**.

## Sobre `const` (aclaración técnica)

Hay un detalle interesante:

```ts
const palabra: string = 'hola'
palabra = 2
```

Incluso si fuera:

```ts
palabra = 'chau'
```

Seguiría siendo error, porque:

- `const` **no permite reasignación**
    
- TypeScript te marcaría otro error adicional
    

Pero en este caso:

- El error de tipo es más importante conceptualmente
    
- El ejercicio cumple su objetivo
