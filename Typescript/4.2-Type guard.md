## ¿Qué significa `data is Product`?

```ts
function isProduct(data: unknown): data is Product
```

Eso se llama un **type predicate** (predicado de tipo).

Se lee así:

> “Si esta función devuelve `true`, entonces `data` **debe ser tratado como `Product`** a partir de ese punto”.

No es un casteo.  
No convierte nada.  
**Le informa al compilador**.

---

## Qué problema resuelve

Cuando recibís datos de una API:

```ts
const data = await response.json();
```

TypeScript **no sabe qué es `data`**.

De hecho, el tipo correcto es:

```ts
unknown
```

Y con `unknown` **no podés acceder a nada**:

```ts
data.price // ❌ Error
```

---

## Qué hace `isProduct`

Tu función:

```ts
function isProduct(data: unknown): data is Product {
  return (
    typeof data === "object" &&
    data !== null &&
    "id" in data &&
    "name" in data &&
    "price" in data
  );
}
```

Hace dos cosas **distintas**:

### 1. En runtime (JavaScript)

Valida que:

- Sea un objeto
    
- No sea `null`
    
- Tenga ciertas propiedades
    

### 2. En compile time (TypeScript)

Le dice al compilador:

> “Si devuelve `true`, podés tratar a `data` como `Product`”

---

## Cómo se usa realmente

```ts
const data: unknown = await response.json();

if (isProduct(data)) {
  data.price; // ✅ TypeScript sabe que es Product
  data.name;  // ✅
} else {
  // ❌ no es Product
}
```

Sin el `data is Product`, esto **no sería posible**.

---

## Diferencia con `as Product` (MUY IMPORTANTE)

### ❌ Casteo (peligroso)

```ts
const product = data as Product;
```

- No valida nada
    
- Si la API cambia → runtime error
    
- TypeScript “confía ciegamente”
    

---

### ✅ Type guard (correcto)

```ts
if (isProduct(data)) {
  // seguro
}
```

- Valida en runtime
    
- Informa al compilador
    
- Es robusto
    

---

## Regla mental clave

> `data is Product` **no transforma el valor**  
> **transforma lo que TypeScript sabe sobre él**

---

## Por qué el retorno es booleano

La función **siempre devuelve `boolean`**, pero:

```ts
data is Product
```

es un **boolean especial**, con semántica de tipo.

---

## Versiones comunes que vas a ver en la industria

```ts
function isUser(x: unknown): x is User
function isOrder(x: unknown): x is Order
function isApiError(x: unknown): x is ApiError
```

Son **type guards**, y se usan todo el tiempo.

---

## Cuándo usarlos

Usalos cuando:

- Consumís APIs
    
- Leés JSON
    
- Recibís `unknown`
    
- Querés seguridad real, no casts
    

---

## En resumen

- `data is Product` = **predicado de tipo**
    
- Le dice a TS: “confiá solo si esto es true”
    
- Es una práctica profesional
    
- No es magia, es contrato
