# `Pick<T, K>` explicado desde cero

## 1. Problema real (antes de `Pick`)

Tenés este tipo base:

```ts
interface User {
  id: string;
  name: string;
  email: string;
  age: number;
}
```

👉 Este tipo representa **al usuario completo**.

---

## 2. Situación real típica

Imaginá esto:

> “Quiero devolver una lista de usuarios,  
> pero **no necesito** email ni age”

En JavaScript **podrías devolver cualquier cosa**, pero **TypeScript necesita un tipo**.

---

## 3. Qué hace `Pick`

```ts
type UserPreview = Pick<User, "id" | "name">;
```

Leé esto así (importante):

> “A partir de `User`, **elegí solo** las propiedades `id` y `name`”

---

## 4. Qué es cada cosa (muy explícito)

```ts
Pick<User, "id" | "name">
```

### `User`

- **TIPO (TypeScript)**: el tipo original completo
    

### `"id" | "name"`

- **TIPO (TypeScript)**: unión de claves
    
- ⚠️ No es un valor, **no es un string en runtime**
    

---

## 5. Resultado de `Pick` (solo tipo)

```ts
type UserPreview = {
  id: string;
  name: string;
}
```

- **TIPO (TypeScript)**: nuevo tipo
    
- **RESULTADO (runtime)**: no existe, esto se borra
    

---

## 6. Uso en una función (acá suele confundir)

```ts
function listUsers(): UserPreview[] {
  return [
    { id: "1", name: "Ana" },
    { id: "2", name: "Juan" }
  ];
}
```

### Qué pasa acá

- El `return`:
    
    - **RESULTADO (runtime)**: array de objetos JS normales
        
- El `UserPreview[]`:
    
    - **TIPO (TypeScript)**: obliga a que cada objeto tenga **solo** `id` y `name`
        

---

## 7. Error bloqueado correctamente

```ts
function listUsers(): UserPreview[] {
  return [
    { id: "1", name: "Ana", email: "a@mail.com" }
  ];
}
```

- **ERROR (TypeScript)**: `email` no existe en `UserPreview`
    
- **RESULTADO (runtime)**: nunca llega, no compila
    

---

## 8. Comparación con escribirlo a mano

### Sin `Pick`

```ts
type UserPreview = {
  id: string;
  name: string;
};
```

Funciona, pero:

❌ duplicás tipos  
❌ si `User` cambia, esto queda desactualizado

---

### Con `Pick`

```ts
type UserPreview = Pick<User, "id" | "name">;
```

✔ reutilizás el tipo base  
✔ mantenés consistencia  
✔ menos errores

---

## 9. Regla mental simple (quedate con esto)

> `Pick` = **“de este tipo grande, agarrá solo estas propiedades”**

Nada más.

---

## 10. Mini ejemplo ultra simple

```ts
type Car = {
  brand: string;
  model: string;
  year: number;
};

type CarLabel = Pick<Car, "brand" | "model">;
```

Resultado:

- **TIPO (TypeScript)**:
    

```ts
{ brand: string; model: string }
```

- **RESULTADO (runtime)**: nada nuevo, solo JS normal
