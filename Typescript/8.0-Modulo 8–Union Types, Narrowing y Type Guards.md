## Objetivo real (industria)

Poder escribir código que:

- Acepte **múltiples formas de datos**
    
- Tome **decisiones seguras**
    
- Evite `any`, `as`, y `if` caóticos
    
- Tenga **autocompletado correcto dentro de cada rama**
    

---

## 1. Union Types

### Qué es

```ts
type ApiResponse = User | Error;
```

Esto significa:

- **TIPO (TypeScript)**: `res` puede ser **User o Error**
    
- **RESULTADO (runtime)**: en ejecución llega **uno u otro**
    

TypeScript **no sabe cuál** hasta que lo comprobás.

---

### Ejemplo

```ts
function handleResponse(res: ApiResponse) {
  console.log(res);
}
```

En este punto:

- **TIPO (TypeScript)**: `User | Error`
    
- ❌ No podés acceder a propiedades específicas todavía
    

```ts
res.email; // ERROR (TypeScript)
```

Porque:

- `Error` no tiene `email`
    

---

## 2. Narrowing (estrechar el tipo)

**Narrowing** = reducir una unión a un tipo concreto **mediante una condición válida**.

---

## 3. Narrowing con `in`

```ts
function handleResponse(res: ApiResponse) {
  if ("email" in res) {
    console.log(res.email);
  }
}
```

### Qué pasa acá

#### Antes del `if`

- **TIPO (TypeScript)**: `User | Error`
    

#### Dentro del `if`

```ts
if ("email" in res) {
```

- TypeScript razona:
    
    > “Solo `User` tiene `email`”
    
- **TIPO (TypeScript)** dentro del bloque: `User`
    
- **RESULTADO (runtime)**: entra solo si la propiedad existe
    

```ts
res.email;
// RESULTADO (runtime): valor del email
// TIPO (TypeScript): string
```

---

## 4. Narrowing con `typeof`

Se usa con **primitivos**.

```ts
function format(value: string | number) {
  if (typeof value === "string") {
    value.toUpperCase();
  }
}
```

### Análisis

- `typeof value === "string"`
    
    - **RESULTADO (runtime)**: compara el tipo JS
        
    - **TIPO (TypeScript)**: value es `string` dentro del bloque
        

```ts
value.toUpperCase();
// RESULTADO (runtime): string en mayúsculas
// TIPO (TypeScript): string
```

---

## 5. Narrowing con `instanceof`

Se usa con **clases**.

```ts
function handle(error: Error | Date) {
  if (error instanceof Error) {
    console.log(error.message);
  }
}
```

- `instanceof`
    
    - **RESULTADO (runtime)**: chequeo de prototipo
        
    - **TIPO (TypeScript)**: narrowing automático
        

---

## 6. Problema real sin Type Guards

```ts
function print(res: User | Error) {
  if ("email" in res) {
    console.log(res.email);
  }
}
```

Funciona, pero:

- La lógica queda **acoplada**
    
- Repetís chequeos
    
- Difícil de reutilizar
    

---

## 7. Custom Type Guards (clave del módulo)

### Qué es

Una función que:

- Devuelve `boolean` en runtime
    
- **Informa a TypeScript** qué tipo es
    

---

### Sintaxis clave

```ts
function isUser(data: unknown): data is User
```

⚠️ Esto es **solo TypeScript**, no JS.

---

### Ejemplo completo

```ts
function isUser(data: unknown): data is User {
  return (
    typeof data === "object" &&
    data !== null &&
    "email" in data
  );
}
```

#### Qué significa `data is User`

- **TIPO (TypeScript)**: si devuelve `true`, `data` es `User`
    
- **RESULTADO (runtime)**: solo devuelve `true` o `false`
    

---

### Uso

```ts
function handleResponse(res: unknown) {
  if (isUser(res)) {
    res.email;
  }
}
```

#### Dentro del `if`

- **TIPO (TypeScript)**: `User`
    
- **RESULTADO (runtime)**: email real
    

---

## 8. Por qué esto es nivel profesional

Este patrón se usa en:

- APIs
    
- Validación de responses
    
- DTOs
    
- Clean Architecture
    
- Repositorios
    
- Frameworks (NestJS, Angular)
    

Ejemplo real:

```ts
if (isApiError(response)) {
  throw new Error(response.message);
}
```

---

## 9. Regla mental definitiva

> Union types describen **posibilidades**  
> Narrowing decide **cuál es real ahora**

## 10. Mini ejercicio para fijar

```ts
type Result = 
  | { success: true; data: string }
  | { success: false; error: string };

function handle(result: Result) {
  if (result.success) {
    result.data;
  } else {
    result.error;
  }
}
```

- `result.success`
    
    - **RESULTADO (runtime)**: boolean
        
    - **TIPO (TypeScript)**: discriminant → narrowing automático
