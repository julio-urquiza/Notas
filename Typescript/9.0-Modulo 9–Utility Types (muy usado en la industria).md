## Idea central del módulo

Los **Utility Types** sirven para:

- Reutilizar tipos existentes
    
- Evitar duplicación
    
- Mantener consistencia entre capas
    
- Modelar casos reales (crear, actualizar, leer)
    

⚠️ **Todos los Utility Types existen solo en TypeScript**  
👉 **No generan código JS**

---

## Tipo base para los ejemplos

```ts
interface User {
  id: string;
  name: string;
  email: string;
  age: number;
}
```

---

## 1. `Partial<T>`

### Qué hace

Convierte **todas las propiedades en opcionales**.

```ts
type UserUpdateDTO = Partial<User>;
```

- **TIPO (TypeScript)**:
    

```ts
{
  id?: string;
  name?: string;
  email?: string;
  age?: number;
}
```

- **RESULTADO (runtime)**: no existe nada nuevo, solo un objeto normal
    

---

### Caso real (API)

```ts
function updateUser(id: string, data: Partial<User>) {
  // data puede traer solo los campos a actualizar
}
```

Uso:

```ts
updateUser("1", { email: "nuevo@mail.com" });
```

✔ Muy común en `PUT` / `PATCH`

---

## 2. `Pick<T, K>`

### Qué hace

Crea un tipo con **solo algunas propiedades**.

```ts
type UserPreview = Pick<User, "id" | "name">;
```

- **TIPO (TypeScript)**:
    

```ts
{
  id: string;
  name: string;
}
```

---

### Caso real

```ts
function listUsers(): UserPreview[] {
  // devuelve info resumida
}
```

---

## 3. `Omit<T, K>`

### Qué hace

Crea un tipo **excluyendo propiedades**.

```ts
type UserWithoutEmail = Omit<User, "email">;
```

- **TIPO (TypeScript)**:
    

```ts
{
  id: string;
  name: string;
  age: number;
}
```

---

### Caso real

```ts
function getPublicUser(): Omit<User, "email"> {
  // no expone email
}
```

---

## 4. `Readonly<T>`

### Qué hace

Hace que **todas las propiedades sean inmutables**.

```ts
type ReadonlyUser = Readonly<User>;
```

- **TIPO (TypeScript)**:
    

```ts
{
  readonly id: string;
  readonly name: string;
  readonly email: string;
  readonly age: number;
}
```

---

### Ejemplo

```ts
const user: ReadonlyUser = {
  id: "1",
  name: "Ana",
  email: "a@mail.com",
  age: 30
};

user.name = "Juan";
// ERROR (TypeScript)
```

- **RESULTADO (runtime)**: JS permitiría el cambio
    
- **TIPO (TypeScript)**: lo bloquea
    

---

## 5. `Record<K, T>`

### Qué hace

Crea un tipo de objeto donde:

- las **claves** son `K`
    
- los **valores** son `T`
    

```ts
type Status = "PENDING" | "APPROVED" | "REJECTED";

type StatusLabels = Record<Status, string>;
```

- **TIPO (TypeScript)**:
    

```ts
{
  PENDING: string;
  APPROVED: string;
  REJECTED: string;
}
```

---

### Uso real

```ts
const labels: StatusLabels = {
  PENDING: "Pendiente",
  APPROVED: "Aprobado",
  REJECTED: "Rechazado"
};
```

✔ TypeScript obliga a definir **todas** las claves

---

## 6. Combinaciones reales (nivel empresa)

### DTO de creación

```ts
type CreateUserDTO = Omit<User, "id">;
```

---

### DTO de actualización

```ts
type UpdateUserDTO = Partial<Omit<User, "id">>;
```

---

### Vista pública

```ts
type PublicUser = Pick<User, "id" | "name">;
```

---

## 7. Regla mental clara

|Utility|Pregunta que responde|
|---|---|
|`Partial`|¿Qué campos puedo enviar opcionalmente?|
|`Pick`|¿Qué campos necesito?|
|`Omit`|¿Qué campos debo ocultar?|
|`Readonly`|¿Qué no se puede modificar?|
|`Record`|¿Qué mapa clave → valor necesito?|

---

## 8. Error común a evitar

❌ Pensar que esto afecta al runtime

```ts
Readonly<User>
```

- **TIPO (TypeScript)**: inmutable
    
- **RESULTADO (runtime)**: objeto normal
    

Para inmutabilidad real → `Object.freeze`
