**PM2** es un **administrador de procesos** para aplicaciones de **Node.js** (aunque también se puede usar con otros lenguajes).  
Su objetivo principal es mantener tus aplicaciones **siempre en ejecución**, gestionarlas fácilmente y facilitar el despliegue en servidores.

👉 En pocas palabras: **es como un "supervisor" que cuida tus aplicaciones en producción.**

---

### 🚀 Funciones principales de PM2:

1. **Mantener procesos corriendo**: reinicia tu app automáticamente si se cae.
2. **Cluster Mode**: permite ejecutar tu aplicación en varios núcleos del CPU para mejorar el rendimiento.
3. **Logs centralizados**: guarda los logs de salida (`console.log`, `console.error`) para monitoreo.
4. **Monitoreo en tiempo real**: puedes ver el estado de todos los procesos (`pm2 monit`).
5. **Start/Stop/Restart fácil**: comandos simples para manejar tus apps.
6. **Configuración con JSON/YAML**: puedes definir cómo correr tus apps con archivos de configuración.
7. **Deployment automático**: incluye herramientas para desplegar en entornos de producción.

---

### 📌 Ejemplos básicos:

1. Instalar PM2 globalmente:

```bash
npm install -g pm2
```

2. Iniciar una aplicación:

```bash
pm2 start app.js
```

3. Ver los procesos en ejecución:

```bash
pm2 list
```

4. Ver logs:

```bash
pm2 logs
```

5. Detener un proceso:

```bash
pm2 stop app
```

6. Guardar configuración para que se reinicie con el servidor:

```bash
pm2 startup
pm2 save
```

---

🔑 En resumen: **PM2 es la herramienta estándar para correr Node.js en producción**, porque asegura que tu aplicación se mantenga viva, optimiza el uso de CPU y facilita el monitoreo.

---

### 1. Crear un proyecto simple en Node.js

Ejemplo de `app.js`:

```js
const http = require("http");
const os = require("os");

const PORT = 3000;

http.createServer((req, res) => {
  res.writeHead(200, { "Content-Type": "text/plain" });
  res.end(`Hola! Servido desde el proceso PID: ${process.pid}\n`);
}).listen(PORT, () => {
  console.log(`Servidor corriendo en http://localhost:${PORT} - PID: ${process.pid}`);
});
```

Si ejecutás `node app.js`, solo usaría **1 núcleo**.

---

### 2. Iniciar con PM2 en modo cluster

```bash
pm2 start app.js -i max
```

- `-i max` → PM2 inicia **tantos procesos como núcleos de CPU tengas**.
- Si querés un número específico (ejemplo 4 procesos):
   ```bash
    pm2 start app.js -i 4
    ```

---

### 3. Ver el estado de los procesos

```bash
pm2 list
```

Vas a ver algo así:

```
┌─────┬────┬──────┬─────────┬──────┬─────────┐
│ id  │ name │ mode │ status │ cpu  │ memory  │
├─────┼────┼──────┼─────────┼──────┼─────────┤
│ 0   │ app │ cluster │ online │  5%  │ 30.0mb │
│ 1   │ app │ cluster │ online │  4%  │ 28.5mb │
│ 2   │ app │ cluster │ online │  6%  │ 29.2mb │
│ 3   │ app │ cluster │ online │  5%  │ 30.1mb │
└─────┴────┴──────┴─────────┴──────┴─────────┘
```

---

### 4. Probar el balanceo de carga

Si hacés varias solicitudes a `http://localhost:3000`, PM2 va a distribuirlas entre los procesos.  
Vas a ver diferentes **PIDs** en la respuesta:

```
Hola! Servido desde el proceso PID: 12456
Hola! Servido desde el proceso PID: 12460
Hola! Servido desde el proceso PID: 12462
```

---

### 5. Logs y monitoreo

- Ver logs:
   ```bash
    pm2 logs
    ```
- Monitoreo en tiempo real:
   ```bash
    pm2 monit
    ```

---

👉 Con esto, tu app de Node.js aprovecha **todos los núcleos** sin que tengas que preocuparte por balanceo de carga manual.
