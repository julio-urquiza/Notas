Kubernetes (a veces lo vas a ver como **K8s**) es una plataforma para **orquestar contenedores**.  
En palabras simples:

> **Kubernetes es como un “sistema operativo” para manejar muchos contenedores Docker a la vez.**

No reemplaza Docker → **lo usa** para correr contenedores.  
Lo que hace es ayudarte a escalarlos, actualizarlos, y mantenerlos funcionando.

---

# 🧩 ¿Qué problema resuelve Kubernetes?

Cuando tenés **1 contenedor**, Docker alcanza.  
Pero cuando tenés:

- 10 microservicios
- 40 contenedores
- varias réplicas de cada uno
- actualizaciones sin cortar el servicio
- balanceo de carga
- contenedores que fallan y deben reiniciarse solos

Docker solo ya no alcanza.

Ahí entra Kubernetes.

---

# 🚀 ¿Qué hace Kubernetes exactamente?

## ✔ **1. Maneja el ciclo de vida de tus contenedores**

- Los inicia
    
- Los reinicia si fallan
    
- Los redistribuye entre servidores
    

## ✔ **2. Escala automáticamente**

- Podés decir: “quiero 5 instancias de esta app”
    
- O: “si hay mucho tráfico, levantá más instancias”
    

## ✔ **3. Hace despliegues sin caídas**

Ejemplo:

- Actualiza tus contenedores uno por uno
    
- Si algo falla, hace rollback solo
    

## ✔ **4. Balancea la carga**

Distribuye el tráfico entre todas las réplicas que tengas.

## ✔ **5. Administra varios servidores como si fueran uno**

Un “cluster” puede tener 3, 10 o 100 máquinas.  
Kubernetes las hace ver como un solo sistema.

---

# 🏗️ Componentes principales (explicado fácil)

### 🟦 **Pod**

La unidad más pequeña.  
Es básicamente **un contenedor o un grupo de contenedores**.

### 🟪 **Deployment**

Define cuántos Pods querés y cómo se actualizan.

### 🟧 **Service**

Expone tu aplicación, por ejemplo en el puerto 3000.

### 🟨 **Node**

Una máquina (física o virtual) donde corren los Pods.

### 🟩 **Cluster**

El conjunto de Nodes manejados por Kubernetes.

---

# 🎯 ¿Para qué sirve Kubernetes en la vida real?

- Microservicios
    
- Apps que necesitan escalar automáticamente
    
- Sistemas con mucho tráfico
    
- Infraestructura distribuida
    
- Despliegues sin downtime
    
- Empresas que usan cloud: GCP, AWS, Azure
    

---

# 🆚 ¿Kubernetes vs Docker?

|Docker|Kubernetes|
|---|---|
|Crea y ejecuta contenedores|Orquesta muchos contenedores|
|Ideal para apps chicas|Ideal para apps grandes o distribuidas|
|Una sola máquina|Muchas máquinas|
|Manual|Automatizado|

Se complementan, no compiten.

---

# 🤓 Ejemplo ultra simple

Querés 5 instancias de tu backend Node con auto-restart:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mi-backend
spec:
  replicas: 5
  selector:
    matchLabels:
      app: backend
  template:
    metadata:
      labels:
        app: backend
    spec:
      containers:
        - name: backend
          image: mi-backend:latest
          ports:
            - containerPort: 3000
```

Kubernetes se encarga de todo lo demás.
