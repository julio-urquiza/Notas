**`log4js`** es una **librería de logging para Node.js**, muy usada para registrar eventos, errores y mensajes del sistema con diferentes niveles (info, warn, error, etc.), formatos y destinos (consola, archivos, bases de datos, etc.).

Podés pensarla como el equivalente a **log4j** de Java, pero adaptada a Node.js.

---

## 🧠 ¿Para qué sirve?

Sirve para:

- Tener **registros organizados** de lo que hace tu aplicación.
- Guardar logs en **archivos rotativos** (por fecha o tamaño).
- Enviar logs a la consola, archivos, HTTP, incluso correo.
- Personalizar el formato y el nivel de detalle (timestamp, nivel, mensaje, etc.).
- Controlar cuánto se imprime (solo errores en producción, más detalle en desarrollo).

---

## ⚙️ Instalación

```bash
npm install log4js
```

---

## 🧩 Uso básico

Un ejemplo simple:

```js
import log4js from 'log4js';

log4js.configure({
  appenders: {
    out: { type: 'console' },           // muestra por consola
    file: { type: 'file', filename: 'logs/app.log' } // guarda en archivo
  },
  categories: {
    default: { appenders: ['out', 'file'], level: 'debug' }
  }
});

const logger = log4js.getLogger();

logger.trace('Esto es trace');
logger.debug('Esto es debug');
logger.info('Servidor iniciado');
logger.warn('Advertencia');
logger.error('Error en conexión');
logger.fatal('Fallo crítico');
```

📄 Se crea un archivo `logs/app.log` con los registros, además de mostrarlos por consola.

---

## 🧱 Niveles de log

De menor a mayor importancia:

|Nivel|Descripción|
|---|---|
|trace|Información muy detallada (debug profundo)|
|debug|Información útil para desarrolladores|
|info|Información general del sistema|
|warn|Advertencias, pero la app sigue funcionando|
|error|Errores que afectan partes del sistema|
|fatal|Errores graves que pueden detener la app|

Podés filtrar por nivel en `categories.default.level`.

---

## 🔁 Rotación de archivos

Podés hacer que los logs se roten automáticamente (por tamaño o fecha):

```js
log4js.configure({
  appenders: {
    file: {
      type: 'dateFile',
      filename: 'logs/app.log',
      pattern: 'yyyy-MM-dd',  // crea uno por día
      compress: true,         // comprime los viejos
      daysToKeep: 7           // guarda solo los últimos 7 días
    }
  },
  categories: {
    default: { appenders: ['file'], level: 'info' }
  }
});
```

## 🧩 Loggers por módulo

Podés tener un logger distinto por cada parte del proyecto:

```js
const userLogger = log4js.getLogger('user');
const dbLogger = log4js.getLogger('db');

userLogger.info('Usuario autenticado');
dbLogger.error('Error al conectar con la base de datos');
```

Y en tu configuración:

```js
categories: {
  default: { appenders: ['out'], level: 'info' },
  user: { appenders: ['file'], level: 'debug' },
  db: { appenders: ['file'], level: 'error' }
}
```

## 💡 Tip: integración con Express

Si usás Express, podés registrar cada request automáticamente:

```js
import express from 'express';
import log4js from 'log4js';

const app = express();

log4js.configure({
  appenders: {
    everything: { type: 'file', filename: 'logs/requests.log' }
  },
  categories: {
    default: { appenders: ['everything'], level: 'info' }
  }
});

const logger = log4js.getLogger();
app.use(log4js.connectLogger(logger, { level: 'info' }));

app.get('/', (req, res) => res.send('Hola Mundo'));
app.listen(3000);
```

Así te loguea cada request entrante con método, ruta, código de estado y tiempo de respuesta.

## 🧰 Alternativas

- **Winston** → más modular, popular en proyectos grandes.
- **Pino** → súper rápido, pensado para alta performance.
- **Bunyan** → formato JSON estructurado.

Pero **log4js** es ideal si venís de Java o querés una configuración clara por archivos.
